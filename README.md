# Orvix

Orvix is a small interpreted programming language built with **Flex**, **Bison**,
and **C**. It demonstrates the main stages of a language implementation:

1. Flex converts source text into tokens.
2. Bison parses those tokens according to the Orvix grammar.
3. The parser builds an abstract syntax tree (AST).
4. The runtime evaluates the AST and executes the program.

Orvix uses **dynamic typing**. A variable does not have a declared type. Its
runtime value can be a number or a string, and the type is determined when the
value is assigned or read with `ACQUIRE`.

## Requirements

- GCC
- Make
- Flex
- Bison
- The Flex development library, usually provided by `libfl-dev`

On Ubuntu or Debian:

```sh
sudo apt update
sudo apt install build-essential flex bison libfl-dev
```

## Build And Run

Run these commands from the repository root:

```sh
make -C examples
make -C examples run
make -C examples && ./examples/orvix examples/conditions.orx
```

The `run` target executes `examples/sum.orx`. It asks for two numbers and prints
their sum.

To run another Orvix program:

```sh
./examples/orvix examples/conditions.orx
```

For example, `conditions.orx` prints values from `1` through `5` and uses an
`if/else` branch to print whether each number is even or odd.

Remove generated files and the executable with:

```sh
make -C examples clean
```

## Language Keywords

| Keyword | Purpose | Example |
| --- | --- | --- |
| `FORGE` | Declares a variable. | `FORGE total;` |
| `SPEAK` | Prints a string or expression. | `SPEAK total;` |
| `ACQUIRE` | Reads a value from standard input. | `ACQUIRE name;` |
| `VERIFY` | Starts an `if` conditional. | `VERIFY (total > 0) { ... }` |
| `DENY` | Starts the optional `else` branch. | `DENY { ... }` |
| `RECUR` | Repeats a block while its condition is true. | `RECUR (count < 3) { ... }` |
| `HALT` | Stops program execution. | `HALT;` |

## Variables And Dynamic Values

Variables are declared with `FORGE` and assigned with `=`:

```orx
FORGE count;
FORGE message;

count = 3;
message = "hello";

SPEAK count;
SPEAK message;
```

The same variable can receive a different runtime type later:

```orx
FORGE value;
value = 42;
SPEAK value;

value = "now a string";
SPEAK value;
```

`ACQUIRE` detects the input type at runtime. An input containing only an
integer becomes a number; any other input becomes a string.

## Conditions And Loops

Use `VERIFY` for an `if` statement and `DENY` for its optional `else` branch:

```orx
VERIFY (count == 0) {
	SPEAK "zero";
} DENY {
	SPEAK "not zero";
}
```

Use `RECUR` for a while-style loop:

```orx
RECUR (count < 3) {
	SPEAK count;
	count = count + 1;
}
```

Numbers are false when they are `0`. Strings are false when empty and true when
non-empty. This truthiness is used by `VERIFY`, `RECUR`, `&&`, and `||`.

## Operators

| Group | Operators |
| --- | --- |
| Arithmetic | `+`, `-`, `*`, `/`, `%` |
| Comparison | `==`, `!=`, `<`, `>`, `<=`, `>=` |
| Logical | `&&`, `||` |
| Unary | `-` |

The `+` operator adds numbers and concatenates values when either operand is a
string. String equality and ordering comparisons are also supported.

Single-line comments begin with `//`:

```orx
// This is an Orvix comment.
```

## Project Files

| File | Description |
| --- | --- |
| `orvix.l` | Flex lexer rules. Converts keywords, identifiers, numbers, strings, operators, and punctuation into tokens. |
| `orvix.y` | Bison grammar and compiler entry point. Parses tokens, creates AST nodes, and starts execution. |
| `src/ast.h` | AST node types and constructor declarations. |
| `src/ast.c` | Allocates and connects AST nodes created by the parser. |
| `src/runtime.h` | Runtime value types and execution function declarations. |
| `src/runtime.c` | Symbol table, dynamic values, expression evaluation, input/output, conditionals, and loops. |
| `examples/sum.orx` | Example that reads two numbers and prints their sum. |
| `examples/conditions.orx` | Example using dynamic values, a loop, and if/else branching. |
| `examples/Makefile` | Builds the generated parser, lexer, and `orvix` executable. |

## Generated Files

`ORVIX.tab.c` is generated by **Bison** from `orvix.y`. It contains the C parser
implementation: token handling, grammar state machines, and calls to the AST
constructors. `ORVIX.tab.h` is the matching generated header containing token
definitions used by the Flex lexer.

`lex.yy.c` is generated by **Flex** from `orvix.l` and contains the C lexer
implementation. These files are build outputs. They should not normally be
edited by hand; change `orvix.y` or `orvix.l` and rebuild instead.

The Makefile generates them inside `examples/.build/`, along with the compiled
`examples/orvix` executable. The `.build` directory and executable are ignored
by Git because they are reproducible build outputs. `make -C examples clean`
removes all of them.

## Build Process In Short

```text
orvix.y  --Bison--> ORVIX.tab.c + ORVIX.tab.h
orvix.l  --Flex---> lex.yy.c
all generated C files + src/*.c --GCC--> examples/orvix
```

The executable expects exactly one source file:

```sh
./examples/orvix path/to/program.orx
```
